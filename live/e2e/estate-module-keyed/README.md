# ec2-module-keyed cohort

Cohort: `ec2-module-keyed`. Generated by `tools/estate-gen` (issue #56) from hashicorp/aws 6.58.0's schema and `internal/live/identity/table.go`'s identity table.

Regenerate with:

```
go run ./tools/estate-gen -cohort ec2-module-keyed -module-wrap -module-keys=a,b -out <dir>
```

Generated with `-module-wrap -module-keys` (issue #59, 59c): every resource
below lives in `wrapped/`, called from a `module "wrapped"` block in the
root's `main.tf` that carries `for_each = toset(["a", "b"])`, so this
estate exercises the five walkers' traversal into a keyed module rather than
a static one. The wrapped module declares a `key` variable that the call
passes `each.key` through as, which is the only way a resource inside the
module can learn its own instance's key.

## Gating

Nothing here runs against a live or emulated cloud by default. The floci-gated
test that does is `internal/live/lifecycle/module_keyed_live_test.go`'s
`TestModuleKeyedForEachAgainstFloci`:

```
TF_FLOCI_TEST=1 go test ./internal/live/lifecycle/ -run TestModuleKeyedForEachAgainstFloci -v
```

It stands this estate up (two EIPs, one per key), reads both live resources'
`tofu-address` tags back with the AWS CLI (not with choudoufu) to confirm
they are literally `module.wrapped["a"].aws_eip.app` and
`module.wrapped["b"].aws_eip.app`, plans clean (the marker discovery proof,
same reasoning as live/e2e/estate-module/'s own gating section), then
removes key "a" from the module call's for_each and checks that the plan
proposes destroying exactly that one instance and nothing for "b" - the
sibling-stability proof that is the whole point of a keyed module over a
counted one (live/LIMITATIONS.md, "child-module": a for_each key does not
renumber the way a count index does).

`terraform validate` passes against the real provider release (6.58.0) this fixture pins.
