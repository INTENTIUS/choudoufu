# networking-advanced cohort

Cohort: `networking-advanced`. Ratified by: the sixth registry-backed
ratification batch against #40's strategy and #44's row generator, issue
#65's recipe — advanced networking (Network Firewall, NetworkManager, VPC
Lattice, Global Accelerator, Route53 Recovery Readiness). Mechanism: #48
(see `live/e2e/estates/example/README.md` for the proof-of-mechanism
cohort). Generated by `tools/estate-gen` (issue #56) from hashicorp/aws
6.58.0's schema and `internal/live/identity/table.go`'s identity table.

This cohort exercises every type this batch ratified into
`internal/live/lint/admission.go` and `internal/live/identity/table.go`.

## Rejected

- **App Mesh** — the batch recipe names it explicitly as a deprecated
  service; skipped entirely, no row-gen proposal even read.
- **`aws_networkfirewall_container_association`** — not a row-gen proposal
  at all: it is classified `cfn-unmodeled` (no CloudFormation Registry type
  models it) as of the provider's 6.59 bump, per the batch recipe's own
  note. Confirmed absent from `tools/row-gen`'s NetworkFirewall section (6
  types: firewall, firewall_policy, logging_configuration, rule_group,
  tls_inspection_configuration, vpc_endpoint_association — no container
  association).
- **Cloud WAN** — not a distinct CFN service. Its constructs
  (`AWS::NetworkManager::CoreNetwork` and friends) are NetworkManager's own
  types, already ratified below; there is no separate `AWS::CloudWAN::*`
  registry namespace to ratify against.

## Deferred, out of this batch's named scope

- **`aws_networkmanager_core_network_policy_attachment`** — row-gen marks
  it `(property-child of AWS::NetworkManager::CoreNetwork) [evidence-only]`,
  a parent-derived fold row-gen does not propose a pastable row for and
  this batch does not construct by hand (row-gen's own non-goals list:
  "no matchTable adoption rows... scope-uniqueness for content-match
  adoption is human judgment"). Left for a future batch.
- **`aws_networkmanager_attachment_routing_policy_label`** — already
  terminal `reasoned-none` in `live/mapping.json`'s sweep overlay
  (`tools/mapping-gen/overlay.d/sweep-residual-ambiguous.json`): "CFN
  models RoutingPolicyLabel as a property on several NetworkManager
  attachment types; the TF resource attaches generically across all of
  them" — no single fold parent. Nothing in this batch changes that
  classification; it is not a ratification candidate at all, and none of
  this batch's `RoutingPolicyLabel`-carrying attachment types
  (`aws_networkmanager_connect_attachment` and friends) claim it as an
  `IdentityAttrs` source.
- **EC2-family networking** (`aws_ec2_*`, `aws_vpc_*`, `aws_vpn_*`,
  `aws_customer_gateway`, transit gateways, VPN connections, prefix lists,
  Direct Connect gateways) — explicitly out of this batch's scope (the
  concurrent `ratify-ec2-networking` batch's own territory). Several of
  this cohort's own types reference such resources by ARN as a required
  argument (`aws_networkmanager_customer_gateway_association`'s
  `customer_gateway_arn`, `aws_networkmanager_vpc_attachment`'s `vpc_arn`
  and `subnet_arns`, and others) — those stay literal placeholder ARNs in
  this cohort's own fixture (`tools/estate-gen/overrides.go`'s
  "networking-advanced cohort" section), the same choice
  `aws_volume_attachment`'s own override makes for `aws_ebs_volume` in an
  earlier batch.

## Gating

`go test ./internal/live/lint/... ./internal/live/identity/...` picks this
directory up through `internal/live/flocitest.FixtureDirs` (#48's union
pin) and checks it by static HCL parse — `TestAdmissionTableCoversEstate`
and `TestTableCoversFixtureTypes` require `admittedTypesV0` and
`DefaultTable` to cover exactly the union of `live/e2e/estate/` and every
`estates/*` cohort, this one included. `internal/live/stamp`'s
`TestTaggableSetCoversAdmissionTable` requires every admitted type to be
pinned taggable or untaggable there too — this batch's forty-four rows are.

`terraform validate` passes against the real provider release (6.58.0)
this fixture pins — confirming every argument name above is real, not just
registry-plausible.

As with every batch before it, this one leaves `live/SURVEY.md` and
`live/LIMITATIONS.md` unrendered — those derive from `admittedTypesV0` and
`DefaultTable` via `go run ./tools/survey-gen -render`, a follow-up commit
after this batch merges (the same two-step issue #65's recipe and every
landed batch's own README have used), not part of this batch's own diff.
`go test ./tools/survey-gen/...` and `internal/live/stamp`'s
`TestUntaggableTypesMatchLimitationsDoc` are red against this branch until
that follow-up render lands — expected, tolerated drift, not a defect in
this batch's own two files (`internal/live/lint/admission.go` and
`internal/live/identity/table.go`) or this cohort.

`live/e2e/run.sh` and the gated `internal/live/discovery` floci integration
