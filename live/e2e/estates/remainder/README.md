## Estate-covered vs identity-only-verified

Building a `terraform-validate`-clean fixture resource, a narrated
Coverage-map row and a hand-verified floci probe for all 192 of this
batch's own admissions is not what ratification gates on: the identity
evidence (the provider's own documented Import section, read and judged
per type) is. So, with the coordinator's own sign-off for this batch
specifically, this cohort holds a **representative 25-type subset**
instead of one resource per admitted type, chosen for service diversity
and a clean `terraform validate` with the least override machinery.
`TestAdmissionTableCoversEstate` and `TestTableCoversFixtureTypes`
(`internal/live/lint/lint_test.go`, `internal/live/identity/identity_test.go`)
were relaxed from an exact bijection to a floor (every fixture type must
be admitted; not every admitted type needs a fixture) specifically to
allow this — see each test's own updated doc comment.

The other **167 types** this batch admits are **identity-only-verified**:
present in `admittedTypesV0` and `DefaultTable`, each one's mechanism
checked against the pinned v6.58.0 provider's own documented Import
section (or, missing one, its Identity Schema or source), but with no
fixture resource and no floci probe. They are listed by service in
"Identity-only-verified types" below, each with its admission mechanism in
one line rather than a full Coverage-map row.

### A correction estate generation caught

`aws_cloudtrail` was accepted as-is from row-gen's raw proposal by this
batch's verification pass (a client-named type via the `arn` argument,
sourced from the provider's own identity schema). Row-gen's `argument:`
line names its source as "provider identity schema
(live/survey-full.json)" — the schema's own `required_for_import` field
name, read literally as a settable configuration argument. Running this
cohort's estate through `terraform validate` refused it directly: `arn` is
Computed-only in the real v6.58.0 wire schema, so `attr("arn")`'s
assumption (this is a configuration argument the run can set) does not
hold. Corrected to `serverAssigned`, discovered by listing, the same
marker path every other CloudTrail-shaped type in this batch takes. This
is the standing argument for keeping a `terraform validate` pass in the
loop even for types a docs-reading verification pass judged clean: the
provider's own wire schema is more precise than its prose docs about which
identity-schema field names are also real configuration arguments.
