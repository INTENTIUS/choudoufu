# ec2-module cohort

Cohort: `ec2-module`. Generated by `tools/estate-gen` (issue #56) from hashicorp/aws's schema and `pkg/identity/table.go`'s identity table.
[GENERATED.md](GENERATED.md) has the provider release, the exact regeneration
command (with `-live-block`, which writes the `live` block in
`versions.tf`) and the provenance table; `tools/estate-gen`'s
`TestModuleFixturesMatchTheGenerator` checks that this directory is that
command's output.

Generated with `-module-wrap` (issue #59, 59b): every resource below lives
in `wrapped/`, called from a `module "wrapped"` block in the root's
`main.tf`, so this estate exercises the five walkers' traversal into a static
module rather than planning at the root.

## Gating

Nothing here runs against a live or emulated cloud by default. The floci-gated
test that does is
`internal/live/lifecycle/module_traversal_live_test.go`'s
`TestModuleTraversalAgainstFloci`:

```
TF_FLOCI_TEST=1 go test ./internal/live/lifecycle/ -run TestModuleTraversalAgainstFloci -v
```

It stands this estate up, reads the live resource's `tofu-address` tag back
with the AWS CLI (not with choudoufu) to confirm it is literally
`module.wrapped.aws_eip.app`, plans clean (which is also the marker
discovery proof: `aws_eip`'s identity is server-assigned, so a clean plan
can only come from listing every EIP and matching this one's tag against
the module-qualified address the traversal computes), runs
`choudoufu live-mv` to cross the module boundary onto `aws_eip.app`, edits
the configuration to match, and plans clean again.

Stock `terraform validate` does not load this directory, since the `live`
block in `versions.tf` is choudoufu's.
