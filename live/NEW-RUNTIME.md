## Base

Built on upstream OpenTofu [`aa3eb66a0c`](https://github.com/opentofu/opentofu/commit/aa3eb66a0c1c792b7751e6ffeef7ca0cd8693f66), version `1.14.0-dev`.

## Gaps

Each row is a gap between OpenTofu's new runtime (`internal/engine`) and what
choudoufu needs, how it is handled while `TOFU_X_EXPERIMENTAL_RUNTIME` is set, and
what closes it. Numbers link to opentofu/opentofu when the row lists them as
upstream, and to choudoufu otherwise.

A run that a refusing row stops falls back to the default runtime for the
whole run ([#2397](https://github.com/INTENTIUS/choudoufu/issues/2397)), with the warning
`Ran on the default runtime, not the new runtime` naming the rows, in place of the
new runtime's own warning, so the output says which runtime ran. Apply follows
the plan: one with an execution graph runs on the new runtime, one without on
the default runtime. `CHOUDOUFU_NEW_RUNTIME_STRICT=1` refuses instead of falling
back; the experimental-runtime lane sets it, so the expected-failures list
measures the new runtime. The `live` row's refusal is not a fallback.

### Refused

With `CHOUDOUFU_NEW_RUNTIME_STRICT=1`, a run that reaches one of these stops with `Not supported on the new runtime yet`, naming the row and what it waits for. Without it, the run falls back to the default runtime, except at the `live` row.

| `replace-cbd-cycle` | cycle on a replace with newly enabled create_before_destroy | on the plan, before it is shown or saved, outside live mode only | a fork port ([#2380](https://github.com/INTENTIUS/choudoufu/issues/2380)), not upstream's code: planning refuses an execution graph with a cycle, naming the operations in it, so a plan cannot half-apply, and the planning and apply engines record create_before_destroy in state. | `removed` | removed blocks | before planning, on the configuration or state | a fork port ([#2409](https://github.com/INTENTIUS/choudoufu/issues/2409)): the planning engine forgets an orphaned or deposed object a removed block with destroy = false covers, instead of deleting it, including at the end of a moved chain, and raises the default runtime's error for a removed block whose resource or module block still exists. A removed block with destroy = true and provisioners is still refused: the default runtime runs them as destroy-time provisioners. In live mode a forget is the default runtime's: the record is deleted in the final write-back pass and the ownership marker stays on the object. With the switch set the port is off and removed blocks are refused again | upstream [`#4686`](https://github.com/opentofu/opentofu/issues/4686), [`#4693`](https://github.com/opentofu/opentofu/issues/4693) |

Discovery binds the object still carrying the old tofu-address to the new address, the projected prior state already holds it there, and the move finishes as an in-place tag update, so the engine never executes a move and ignores the statement, whose old address has no state entry. That holds for the shapes internal/live/moved's Honourable admits, which are the ones internal/live/lint admits and discovery aliases; every other moved block is refused here, as lint refuses it on either runtime | a moved block whose endpoints an ownership marker can follow, or choudoufu live-mv, which rewrites the marker directly |

With the switch set the port is off and validation blocks are refused again | removed, package and call site and this row's fork_port, when the new runtime accepts a condition derived from a sensitive value; upstream, not yet filed separately |
| `lifecycle-destroy` | lifecycle { destroy } | before planning, on the configuration or state | a fork port ([#2409](https://github.com/INTENTIUS/choudoufu/issues/2409)): lifecycle { destroy = false } is recorded on the object in state, an orphaned or deposed object it or its state covers is forgotten instead of deleted (a count or for_each reduction, enabled = false, a destroy plan), a replace becomes ForgetThenCreate, and a destroy that forgot objects fails with the default runtime's error unless -suppress-forget-errors is set. With the switch set the port is off and the argument, and an object whose state records it, are refused again | upstream [`#4682`](https://github.com/opentofu/opentofu/issues/4682) |
| `checks-conditions` | checks and conditions | before planning, on the configuration or state | a fork port ([#2409](https://github.com/INTENTIUS/choudoufu/issues/2409)), not upstream's code: check blocks and resource preconditions and postconditions are evaluated inside the new runtime's evaluator, with the default runtime's diagnostics. A resource's preconditions guard its configuration, so a failing one stops it from being planned or applied; its postconditions are checked against the planned and then the applied result, so an apply-time failure is reported after the object is saved; a check block's assertions are checked at the end of a plan and of an apply, and a failure is a warning. A resource condition failure is a warning in a refresh-only plan and is not reported by a destroy plan's refresh or by validate, as in the default runtime. Output preconditions were already upstream's. Check results are not recorded in the plan or state (C3, [#2410](https://github.com/INTENTIUS/choudoufu/issues/2410)), so a plan's JSON and show carry no condition_results; a check block's scoped data source is still refused by the data-sources row. With the switch set the port is off and these blocks are refused again | removed, package and call sites and this row's fork_port and switch, when upstream's checks and conditions land; upstream [`#4390`](https://github.com/opentofu/opentofu/issues/4390) |
| `sensitive` | sensitive values (mark handling) | before planning, on the configuration or state | a fork port ([#2410](https://github.com/INTENTIUS/choudoufu/issues/2410)): upstream's evaluator marks sensitive variables, outputs and sensitive() results, but drops the marks where a value leaves evaluation; the port marks a planned change's prior and planned values (the configuration's sensitive paths, outside ignore_changes, and the schema's sensitive attributes), plans a change of sensitivity alone as an update, stores a root output unmarked with its sensitive flag, and refuses a root output whose value is sensitive but not declared sensitive, as the old runtime does. With the switch set the port is off and sensitive = true variables and outputs and the sensitive() function are refused again. An applied object is stored with its sensitive paths (the planned value's and the schema's) by an unconditional fork fix in internal/engine/applying, not by the port, so a schema-sensitive attribute reaches state and live-mode records as sensitive with the switch set too | removed, package and call sites and this row's fork_port, when upstream [`#4360`](https://github.com/opentofu/opentofu/issues/4360) lands |
| `deferral` | deferred actions | inside planning | error on any deferral not caused by -target or -exclude; plans have no record of deferral, so a post-plan check cannot see one. The deferral fork port ([#2382](https://github.com/INTENTIUS/choudoufu/issues/2382)) marks what -target or -exclude deferred with a mark of its own, so a resource whose configuration is derived only from such a result is left out of the plan as the old runtime leaves it, and gives an unknown count or for_each the old runtime's "Invalid count argument" or "Invalid for_each argument" error. Every other deferral is still refused. With the switch set the port is off and this row refuses those deferrals again | upstream [`#4697`](https://github.com/opentofu/opentofu/issues/4697) |

## Fork ports

A fork port fills a gap with choudoufu's own code in
`internal/engine/forkport/<name>` until upstream's lands. `CHOUDOUFU_NEW_RUNTIME_NO_FORK_PORTS=1`
turns every port off, and a port's own switch turns it off alone; off, the gap
row that refused the construct before the port refuses it again.
`scripts/upstream-sync.sh --report` prints `EXPIRE: remove port <name>` once a
port's expiry issues have all closed.
