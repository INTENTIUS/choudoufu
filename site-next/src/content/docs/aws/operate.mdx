Day two is stock OpenTofu with tag writes in place of state moves. [Day-2 operations](/choudoufu/docs/use/day2/) indexes every task.

## Rename

A `moved` block works as in stock, and so does `choudoufu live-mv <old> <new>`, which rewrites the `tofu-address` tag. The plan shows no destroy and no create. [Rename a resource](/choudoufu/docs/use/rename-a-resource/).

## Remove

Delete the block and the object is destroyed, children first. To let go of something without destroying it, use the [ownership policy](https://github.com/INTENTIUS/choudoufu/blob/main/live/OWNERSHIP-POLICY.md); its `threshold` refuses a run that deletes more than you allowed. [Remove a resource](/choudoufu/docs/use/remove-a-resource/).

## Scale

Scaling a `count` down and up touches only the instances stock would. A pool of lookalike members carries a third tag, `tofu-slot`, so survivors keep their identity.

## Plan, review, apply

`apply FILE` reads a saved plan as an approval. It replans against the live system and applies only on a match. If they differ it changes nothing, prints `The approved plan no longer matches the live system`, and exits 3 for a pipeline to route back to review.

## From CI

Five jobs: `live-check` and `live-plan` on a pull request, `live-apply` and `live-adopt` behind approvals, and `live-discover` on a cron. [CI how-to](/choudoufu/docs/use/cicd/).

## Two runs at once

There is no lock. Each create carries its tags, so the second run sees the first one's object on its next plan. [CONCURRENCY.md](https://github.com/INTENTIUS/choudoufu/blob/main/live/CONCURRENCY.md).
