An estate owns the resource groups its configuration declares. An operator applies two templates once:

```
az deployment sub create --location <region> \
  --template-file live/azure/estate-grant.json \
  --parameters estate=<estate> resourceGroups='["<rg>"]' principalId=<object-id>
az deployment sub create --location <region> \
  --template-file live/azure/estate-boundary.json \
  --parameters estate=<estate> resourceGroups='["<rg>"]'
```

## What that buys

The grant gives one principal a role on the estate's groups, and that role alone decides who may delete. The Policy denies a write whose `tofu-estate` is missing or names another estate. `deleteLock=true` adds an opt-in lock on deleting a tagged resource; it refuses the estate's own destroys too, so each one then needs an `az policy exemption create` on the lock. Handing over moves the role assignments.

## Guarding the marker

The Policy applies to every caller, the estate's own included, so no write removes or rewrites `tofu-estate` on a resource in the estate's groups ([GATE.md](https://github.com/INTENTIUS/choudoufu/blob/main/live/azure/GATE.md)).
