```
choudoufu live-check
```

It runs offline and names the fix for each refusal. A marker exists before its resource, so the name must come from configuration alone.

## The backend

A `backend` or `cloud` block is refused because the markers record ownership. Non-default workspaces and `force-unlock` are refused too.

## Expansions and identity arguments

`count` and `for_each` work over configuration and data sources. Names from `uuid()` or a module output are refused. [LIMITATIONS.md](https://github.com/INTENTIUS/choudoufu/blob/main/live/LIMITATIONS.md) lists each refusal with its fix.

## Resource types

Every AWS type is admitted except three that mint credentials. [READINESS.md](https://github.com/INTENTIUS/choudoufu/blob/main/live/READINESS.md) has the tiers.

## Running it

`plan -out`, `apply <planfile>` and `-target` work.

## Other providers

Another provider's type is admitted when configuration resolves its identity. Otherwise it is refused as `unadmitted-type` ([COMPATIBILITY.md](https://github.com/INTENTIUS/choudoufu/blob/main/live/COMPATIBILITY.md)).
